# KINGMAST v0.0.8 — Software release checkpoint

Date: 2026-09-11  
Status: development software checkpoint; warning-only Level 0 research platform.

## Scope

v0.0.8 consolidates the software work delivered after the v0.0.7 checkpoint:

- predictive Navigation Horizon with bounded lookahead and endpoint-preserving route compaction;
- calibrated front/rear/left/right camera identity, surround readiness and cross-camera object association;
- lane corridor, free-space and traffic-control scene estimation with freshness/confidence gates;
- trusted-device-first driver identity, profile preferences and privacy-gated profile memory;
- storage-boundary purge when personalization or location history is disabled;
- role-aware vehicle access for Owner/Admin/Driver/Guest/Valet/Service;
- delegated Digital Key issuance with permission ceilings, expiry limits, revocation rules and last-owner protection;
- Ed25519 operator-to-profile binding for access mutations and self-scoped HMI access views;
- NextgenRuntime wiring into the risk-engine server and attention-safe predictive HMI surfaces;
- bounded latest-frame camera buffering with drop-oldest behavior under inference/network pressure;
- stale/future camera-frame rejection and server-side P50/P95/drop-rate runtime health classification;
- parked-only camera diagnostics and attention-safe degraded/overloaded warnings;
- replay-safe camera publishing: each signed frame is submitted at most once;
- bounded publisher backoff and OpenCV/RTSP source reconnect while preserving newest-frame semantics;
- configurable edge inference image size/device/FP16 plus thermal monitoring, hysteresis and cadence reduction;
- Raspberry Pi 5 CPU and Jetson CUDA runtime profiles documented as tuning starting points, not qualification claims.

## Safety boundary

The product version changes to **0.0.8**, but authority does not change:

- no steering command authority;
- no braking command authority;
- no throttle/acceleration command authority;
- no gear, torque or drivetrain command authority;
- no vehicle-control CAN-write path;
- perception, navigation, identity and health outputs remain advisory/read-only;
- `controlAuthority: none` remains the next-generation runtime contract.

## Verification boundary

CI, CodeQL, deterministic software tests, browser HMI tests and software evidence gates may verify the v0.0.8 codebase. They do **not** imply that physical HIL, closed-track, target-hardware, public-road or homologation evidence from earlier campaigns has been re-run.

Historical artifacts explicitly bound to `V006`, `V007` or `v0.0.7` remain historical and are not silently relabeled as v0.0.8 evidence.

## Compatibility and migration

- Existing API path generations such as `/v3`, `/v4` and `/v5` remain interface versions, not product-version identifiers.
- Existing `kingmast:v006:*` local-storage namespaces are retained for compatibility because the persisted schema was not intentionally migrated by this release.
- Existing authenticated ingress/message formats remain compatibility contracts unless separately versioned.
- No user profile, Digital Key or historical evidence record is automatically promoted merely because the software version changed.
