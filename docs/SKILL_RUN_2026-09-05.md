## Confirmed findings and actions

### P0/P1 — lateral detection was still able to create text alerts from distance alone

The perception severity used by the current simulator and edge fusion is distance-based. A left/right motorcycle, bicycle or person could therefore become `critical` simply because it crossed the close-distance threshold. That is not a dedicated lateral-collision assessment and conflicts with the driver-attention policy.

Action:
- left/right detections remain in the object / vehicle spatial view;
- left/right detections no longer create textual driver alerts from distance severity alone;
- a future lateral textual warning requires its own validated collision-risk signal rather than overloading proximity severity;
- unit and source-contract regression coverage lock the rule.

This preserves detection visibility without pulling the driver's focus away from the road scene.

### P1 — read paths mutated alert runtime/history

`currentEnvelope()` previously called the stateful alert stabilizer and wrote the event buffer even when invoked from read-only paths such as latest-state reads, assistant context and initial WebSocket state.

Action:
- `AlertStabilizer.preview()` evaluates the current alert presentation on a cloned state;
- read paths use preview and remain side-effect free;
- publish/ingress paths alone commit stabilizer state and event history;
- tests prove preview does not mutate committed alert state.

This restores the architecture rule that reads must not create domain history.

## HMI / UX skill

The implemented rule remains: one primary textual driving warning owns attention. Side-object location is better communicated spatially around the vehicle than as a duplicate alert card.

The change is consistent with the existing KINGMAST Apple-inspired hierarchy and progressive-disclosure rules. It does not copy an Apple layout or asset.
